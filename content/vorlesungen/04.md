## Zusammenfassung

### Teil 1 – Das String-Objekt (vorl4, Folien 3–13)

📘 Strings sind Objekte. `new String("…")` und die Kurzform `"…"` erzeugen beide ein String-Objekt, auf das man über die Variable
zugreift (Folien 3–4). Objekte im Detail folgen in der nächsten Vorlesung.

📘 Die wichtigsten Methoden am Beispiel `"Sein oder Nichtsein"`:

| Methode | Was sie tut | Beispiel | Ergebnis |
|---|---|---|---|
| `charAt(n)` | Zeichen an Position `n` (Zählung ab 0) | `text.charAt(10)` | `"N"` |
| `indexOf(s)` | erste Position von `s`, sonst `-1` | `text.indexOf("oder")` | `5` |
| `indexOf(s, ab)` | wie oben, Suche ab Position `ab` | `text.indexOf("ein", 5)` | `16` |
| `lastIndexOf(s)` | Suche von hinten | `text.lastIndexOf("ein")` | `16` |
| `substring(a, b)` | Teilstring von `a` bis **vor** `b` | `text.substring(5, 9)` | `"oder"` |
| `split(t)` | zerlegt am Trennzeichen in ein Array | `text.split(" ")` | `["Sein", "oder", "Nichtsein"]` |

📘 Merksätze aus den Folien: Ob eine Zeichenfolge vorkommt, prüft man mit `indexOf(...) != -1` (Folie 8). `substring` kopiert das
Zeichen an der Endposition **nicht** mit, und ein zu großer Endwert erzeugt keinen Fehler (Folien 11–12).

### Teil 2 – Eingaben über Formulare (vorl4, Folien 17–52)

📘 Ein Formular steht in `<form>` … `</form>` und wird in JavaScript durch das **Form-Objekt** dargestellt (Folie 17). Ansprechen
kann man es über das Array `document.forms[0]` oder besser über seinen Namen bzw. seine `id`, denn bei vielen Formularen ist eine
Nummer schwer zu lesen und ändert sich, sobald ein Formular dazukommt (Folien 18–19). Genauso gibt es für die Elemente eines
Formulars das Array `elements` oder den Zugriff über Namen und `id` (Folien 20–21).

📘 Die Formularelemente im Überblick:

| Element | HTML | Wichtig in JavaScript |
|---|---|---|
| Textfeld | `<input type="text">` | `value` lesen/setzen, `onchange` feuert erst beim Verlassen des Felds (Folien 26–28) |
| Mehrzeilig | `<textarea rows cols>` | Starttext steht **zwischen** den Tags, nicht in `value` (Folie 29) |
| Passwort | `<input type="password">` | nur die Anzeige ist versteckt – JavaScript liest Klartext, übertragen wird ohne Verschlüsselung (Folien 31–32) |
| Versteckt | `<input type="hidden">` | wird nicht angezeigt, zum Zwischenspeichern (Folie 33) |
| Schaltflächen | `button`, `submit`, `reset` | `onclick`; Submit verschickt, Reset setzt zurück (Folien 34–36) |
| Checkbox | `<input type="checkbox">` | `checked` ist `true` oder `false` (Folien 37–39) |
| Radiobuttons | gleicher `name` = eine Gruppe | nur einer wählbar; welcher, findet man nur mit einer **Schleife** (Folien 40–43) |
| Auswahlliste | `<select>` mit `<option>` | `selectedIndex`, mit `multiple` Mehrfachauswahl, `new Option()` fügt hinzu (Folien 44–52) |

> 🤖 **KI-Erklärung – warum eine Schleife bei Radiobuttons?** Eine Radio-Gruppe ist in JavaScript eine Liste von Elementen.
> Es gibt keine Eigenschaft „gewählter Wert der Gruppe“, also fragt man jedes Element nach `checked`. Moderne Alternative:
> `document.querySelector('input[name="auswahl"]:checked').value`.

### Teil 3 – Webseiten bauen: Struktur mit HTML (HTML3)

📘 Erst skizzieren, dann gliedern, dann HTML schreiben: Tobis Segway-Tagebuch wird zuerst in **Blöcke** zerlegt, danach kommen die
Feinheiten (HTML3, Folien 3–14, 55).

- **Zitate:** `<q>` für kurze Zitate im Fließtext, `<blockquote>` für lange Zitate als eigener Block (Folien 15–25).
- **Block- vs. Inline-Elemente:** Block-Elemente (`<p>`, `<blockquote>`, `<h1>`) stehen mit Umbruch davor und danach, Inline-Elemente
  (`<q>`, `<em>`, `<a>`) fließen im Text mit (Folie 25).
- **`<br>`** erzwingt einen Zeilenumbruch. Es ist ein **leeres Element** ohne Inhalt und ohne End-Tag, genau wie `<img>` (Folien 28–30).
- **Listen in zwei Schritten:** jeden Eintrag in `<li>` packen, dann alles in `<ol>` (geordnet, nummeriert) oder `<ul>` (ungeordnet)
  (Folien 34–39). Für Listen nie `<p>` nehmen: Man wählt immer das Element, das der **Bedeutung** des Inhalts entspricht (Folien 35–36).
- **Verschachtelung als Baum:** `<html>` ist die Wurzel, `<head>` und `<body>` sind seine Kinder (Folien 45–46). Wer den Baum versteht,
  verhindert nicht zusammenpassende Tags (Folie 47).

### Teil 4 – CSS: Style für die KopfüBar (HTML4, HTML5)

📘 Eine CSS-**Regel** besteht aus einem **Selektor** und Deklarationen aus **Property** und **Wert**, jede endet mit `;`
(HTML5, Folie 31). Mehrere Selektoren trennt man mit Komma: `h1, h2 { … }`. Für ein Element darf es beliebig viele Regeln geben,
sie werden zusammengeführt (HTML4, Folien 19–22).

📘 Statt das CSS in jede Seite zu kopieren, kommt es in eine **externe Datei** `bar.css`, die jede Seite mit `<link>` einbindet –
aus den Unterordnern mit relativem Pfad `../bar.css` (HTML4, Folien 28–32). Das verbindet sich direkt mit Vorlesung 3.

📘 **Vererbung:** Viele Styles wie `font-family` erben Kindelemente von ihren Eltern. Darum gehört die Schrift in die Regel für
`<body>` (HTML5, Folien 3–4). Gibt es eine spezifischere Regel, gewinnt sie (Folie 11).

📘 **Klassen:** Mit `class="gruenertee"` im HTML und dem Selektor `p.gruenertee` oder `.gruenertee` im CSS gestaltet man gezielt
einzelne Elemente. Ein Element darf mehrere Klassen haben: `class="gruenertee himbeer blaubeer"` (HTML5, Folien 13–25). Bei
Konflikten entscheidet die spezifischste bzw. die zuletzt stehende Regel (Folie 23). Gültigkeit prüft der **W3C-Validator** (Folie 29).

> 🤖 **Verbindung zu diesem Portfolio:** Genau so ist diese Website gebaut. `css/style.css` gilt für alle Seiten, die Farben stehen
> als Variablen in einer einzigen Regel für `:root`, und die Farbschemata sind nichts anderes als zusätzliche Regeln für
> `<html data-farbe="…">`.

## Beispiele

📘 Die String-Methoden aus der Tabelle zum Ausprobieren (vorl4, Folien 5–13):

```js
const text = "Sein oder Nichtsein";
console.log(text.charAt(10));            // N
console.log(text.indexOf("oder"));       // 5
console.log(text.indexOf("ein"));        // 1
console.log(text.indexOf("ein", 5));     // 16
console.log(text.lastIndexOf("ein"));    // 16
console.log(text.indexOf("Hamlet"));     // -1 → kommt nicht vor
console.log(text.substring(5, 9));       // oder
console.log(text.split(" "));            // [Sein, oder, Nichtsein]
```

🤖 Komma statt Punkt – der Kern der Abgabe-Übung. `replace` ersetzt das **erste** Vorkommen, `toFixed(2)` rundet auf zwei Stellen:

```js
const eingabe = "100,4";
const betrag = parseFloat(eingabe.replace(",", "."));
console.log(betrag);                                  // 100.4
console.log((betrag * 0.86).toFixed(2).replace(".", ","));   // 86,34
console.log(parseFloat("abc"));                       // NaN → keine Zahl
```

📘 Checkbox auslesen (vorl4, Folie 38):

```html
<form id="meinFormular" name="meinFormular">
  <input type="checkbox" id="auswahl" name="auswahl">
  <input type="button" value="Anzeigen" onclick="test()">
</form>
<script>
  function test() {
    if (document.meinFormular.auswahl.checked) alert("Das Feld ist markiert!");
    else alert("Das Feld ist nicht markiert!");
  }
</script>
```

📘 Externes Stylesheet einbinden (HTML4, Folie 30):

```html
<head>
  <meta charset="utf-8">
  <title>KopfüBar</title>
  <link type="text/css" rel="stylesheet" href="bar.css">
</head>
```

### Übung – Währungsumrechner (Abgabe, vorl4 Folie 53)

📘 Schreibe einen Währungsumrechner, der zwischen zwei Währungen umrechnet, z. B. $ und €. Die Eingabe läuft über ein Formular mit
Textfeld und Auswahl-Buttons, die Ausgabe in ein Formular-Textfeld. Ein- und Ausgabewerte werden mit **Komma** geschrieben
(Funktion `replace` verwenden). Beim Klick auf „Umrechnen“ holt eine Funktion die Werte aus dem Eingabeformular und schreibt das
Ergebnis ins Ausgabeformular.

✏️ Mein Code liegt im Repo `wp-aufgaben-3-semester`, Ordner `26.10_aufgabe1_waehrungsrechner/`.

**▶ [Währungsumrechner live ansehen](aufgaben/26.10_aufgabe1_waehrungsrechner/index.html)**

<details>
<summary>Lösung</summary>

```javascript
const KURS = 0.86;   // 1 Dollar = 0,86 Euro

function umrechnen() {
  const eingabe = document.getElementById("betrag").value;      // immer ein String
  const betrag = parseFloat(eingabe.replace(",", "."));         // "100,4" → 100.4

  if (isNaN(betrag)) {
    document.getElementById("ergebnis").value = "Bitte eine Zahl eingeben";
    return;
  }

  let ergebnis;
  if (document.getElementById("dollarNachEuro").checked) {
    ergebnis = betrag * KURS;
  } else {
    ergebnis = betrag / KURS;
  }

  document.getElementById("ergebnis").value = ergebnis.toFixed(2).replace(".", ",");
}
```

🤖 **Warum funktioniert das?**
- `value` eines Textfelds ist immer ein String (vgl. `prompt` in Vorlesung 2). Erst `replace` macht aus dem Komma einen Punkt, dann
  wandelt `parseFloat` den String in eine Zahl.
- Die beiden Radiobuttons haben denselben `name`, deshalb ist immer genau einer gewählt. Abgefragt wird nur einer über `checked`.
- `type="button"` statt `submit`: Sonst würde der Browser das Formular abschicken und die Seite neu laden.
- `toFixed(2)` liefert einen String mit zwei Nachkommastellen, `replace` macht den Punkt wieder zum Komma.

🤖 **Code-Check:** Erfüllt die Aufgabe. Ideen: Eingaben wie `1.000,50` (Tausenderpunkt) werden falsch gelesen, weil `replace` nur das
erste Zeichen ersetzt – `replaceAll(".", "").replace(",", ".")` wäre robuster.

</details>
