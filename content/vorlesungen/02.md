### Teil 1 – HTML: Wie das Web funktioniert

📘 Um eine Webseite zu erstellen, schreibt man Dateien in **HTML** und legt sie auf einem **Webserver** ab. Von dort kann jeder
Browser die Seiten über das Internet abrufen (HTML1, Folie 6).

✏️ Meine Notiz auf der Folie: **Web 1.0**. Auf dem Server liegen HTML, CSS und (Java)Script. Die Verbindung läuft über **http**.

📘 Der **Webserver** ist ein Computer, der mit dem Internet verbunden ist und auf Anfragen von Browsern wartet. Er hält
**HTML-Dateien, Bilder, Musik und andere Dateitypen** bereit. Findet er die angefragte Ressource, schickt er sie an den Browser
(HTML1, Folie 7). Der **Browser** fordert die Seite an und zeigt sie an. Wie sie aussehen soll, erfährt er aus dem HTML
(HTML1, Folie 8).

✏️ Der Server **bietet Services an**. Der Browser (Client) schickt eine **http-Anfrage** („Ich brauche die HTML-Datei bar.html“),
der Server eine **http-Antwort** („Hab sie gefunden. Bitte sehr!“).

> 🤖 Das ist genau das, was passiert, wenn du dieses Portfolio über `python3 -m http.server` öffnest: Im Terminal siehst du
> jede Anfrage als Zeile, z. B. `GET /content/vorlesungen/02.md 200`. `200` ist die Antwort „gefunden“. Unter
> [Über das Projekt](ueber.html) gibt es dazu eine Animation.

### Teil 2 – HTML: Tags, Elemente, Struktur

📘 Am Beispiel **KopfüBar** zeigt das Skript, wie HTML aussieht: `<h1>` für die Überschrift, `<img>` für ein Bild, `<p>` für
Absätze, `<em>` zum Hervorheben, `<h2>` für eine Zwischenüberschrift (HTML1, Folien 9–12).

✏️ Meine Notizen auf Folie 10: `<head>` ist ein **öffnendes Tag**, `</head>` ein **schließendes Tag**. Der `<title>` ist der Name,
der **im Tab angezeigt** wird. Der `<body>` enthält die eigentliche **Struktur** der Website.

📘 **HTML** heißt **HyperText Markup Language**. Man „markiert“ Text mit Tags, damit der Browser die Struktur erkennt
(HTML1, Folie 13). Aus den „Es gibt keine dummen Fragen“-Folien (HTML1, Folien 14–20):

- Der Browser stellt die Elemente nach **eingebauten Standardregeln** dar. Mit **CSS** legt man eigene Regeln fest.
- Browser **ignorieren Whitespace**: Tabulatoren, Zeilenumbrüche, mehrere Leerzeichen. Einrückungen machen den Code nur für uns lesbar.
- Es gibt sechs Überschriftenebenen, `<h1>` bis `<h6>`. Meist reichen `<h1>` bis `<h3>`.
- Am `<html>`-Tag erkennt der Browser, dass das Dokument HTML ist. Man sollte es nie weglassen.
- Eine HTML-Datei ist eine **einfache Textdatei** ohne Formatierung. Die Endung `.html` sagt dem Betriebssystem, welcher Dateityp es ist.
- Das Web basiert auf Textdateien. So kann **jeder Browser** überall die Seite verstehen.
- **Kommentare** stehen zwischen `<!--` und `-->`. Der Browser ignoriert alles dazwischen, auch HTML-Code.

✏️ Zu „HyperText“ habe ich notiert: Der Name ist ein Modename, „no reason“. Wichtig sind **Links** und **Markup-Sprache**.

📘 **Tags seziert** (HTML1, Folien 57–59): Ein Tag besteht aus dem Tag-Namen in spitzen Klammern. Start-Tag und End-Tag
bilden ein **Tag-Paar**. Das schließende Tag erkennt man am `/`.

> **Element = Start-Tag + Inhalt + End-Tag** (HTML1, Folie 59)

📘 Tag-Paare müssen nicht in derselben Zeile stehen. Start- und End-Tag sollten aber immer zusammenpassen. Manche Elemente wie
`<img>` haben nur ein Tag. Elemente werden **ineinander verschachtelt**, z. B. `<head>` und `<body>` in `<html>`
(HTML1, Folien 60–64).

📘 **Attribute** geben einem Element zusätzliche Informationen, z. B. `<p id="Hausmischung">` (HTML1, Folie 65, Kopfnuss)
oder `<style type="text/css">` (Folie 70).

✏️ Meine Notiz auf HTML1, Folie 36: Ich habe den **DOM-Baum** gezeichnet (`html` → `head` und `body` → `title`, `h1`, `h2`, `p`).
Dazu: `<p id="Hausmischung">`. Die `id` ist ein Name, über den man das Element später ansprechen kann, z. B. mit JavaScript.

> ❓ Meine Handschrift auf HTML1, Folie 36 ist an dieser Stelle schwer zu lesen. Der Sinn „`id` = Name für den JavaScript-Aufruf“
> passt aber zu JS2, Folie 6, wo `document.getElementById('absatz')` genau so ein Element findet.

### Teil 4 – JavaScript: Was es kann

📘 Drei kleine Programme zeigen, was JavaScript kann (JS2, Folien 6–9):

- **Inhalt ändern:** `document.getElementById('absatz').innerHTML = 'Veränderter Inhalt'`
- **Layout ändern:** `document.getElementById('absatz').style.color = 'red'`
- **Betriebssystem-Funktionen nutzen:** `Date()` liefert Datum und Uhrzeit

✏️ Meine Notiz: Das ist **JavaScript** mit einem **Event** (der Klick) und einem **Eventhandler** (`onclick`). Bei `.style.` habe
ich eingekreist: Darüber ändert JavaScript das CSS.

📘 **JavaScript in eigene Dateien schreiben** (JS2, Folie 13): `<script src="meinScript.js"></script>`.

✏️ Meine Notiz dazu: Im `<head>` kann man so, wie mit `import` in Java, **Bibliotheken** von JavaScript-Dateien „herunterladen“.

📘 **`"use strict";`** (JS2, Folie 14) schaltet die moderne Ausführung ein, in der viele fehlerhafte Stellen beseitigt sind.
Es muss ganz am Anfang des Codes stehen und lässt sich nicht rückgängig machen. Früher schrieb man `type="text/javascript"`,
heute reicht ein einfaches `<script>`-Tag (JS2, Folie 11).

📘 **Eingaben aufnehmen** (JS2, Folie 15): `prompt("Wie alt sind Sie?")` öffnet ein Eingabefenster und gibt die Eingabe zurück.

📘 **Kontrollausgaben** (JS2, Folien 20–24): `console.log()` schreibt in die **JavaScript-Konsole** der Entwicklertools
(Windows: `F12`, Mac: `⌘ + ⌥ + I`). Das `console`-Objekt kennt auch `clear()`, `error()`, `info()`, `warn()` und `trace()`. Jeder
Browser hat außerdem einen Debugger mit Breakpoints.

📘 **Werkzeuge** (JS2, Folien 3–4): Visual Studio Code als Editor. **node.js** ist eine Laufzeitumgebung, mit der JavaScript ohne
Browser und auch auf dem Server (Backend) läuft. Prüfen mit `node -v` und `npm -v` im Terminal.

### Teil 5 – JavaScript: Variablen und Datentypen

📘 **Dynamische Typisierung** (JS2, Folie 25): In Java hat jede Variable einen festen Typ, den der Compiler prüft. JavaScript ist
**vollständig dynamisch typisiert**: Typen werden erst zur Laufzeit ermittelt. Man gibt keinen Typ an. Eine Variable kann später
einen Wert eines anderen Typs bekommen: aus `let num = 2` kann `num = "Hallo"` werden (JS2, Folien 26, 32).

📘 **Variablen anlegen** (JS2, Folien 26, 33):

| Schlüsselwort | Gültigkeit | Wann? |
|---|---|---|
| `let` | nur im selben Block `{ }` | wenn die Variable einen neuen Wert bekommt („empfohlen“) |
| `const` | wie `let` | wenn der Wert gleich bleibt (Konstante) |
| `var` | global bzw. in der ganzen Funktion | nur in Ausnahmefällen, älter, mit Besonderheiten |

✏️ Meine Notizen: neben `let` „global für gesamte Website“, neben `const` „z. B. 22“.

> ❓ Die Notiz „global für gesamte Website“ steht neben `let`. Laut Folie 26 gilt `let` aber nur im Block. Wahrscheinlich gehört die
> Notiz zu Variablen ganz ohne Schlüsselwort (Folie 34). Bitte prüfen.

📘 **Datentypen:** Boolean, Number (keine Unterscheidung zwischen Ganz- und Kommazahl), String, Objekte (JS2, Folien 26–27).
**Strings** stehen in `'…'`, `"…"` oder Backticks `` `…` ``. Anfang und Ende müssen gleich sein. Mit dem **Backslash** maskiert
man Sonderzeichen: `\"` für ein Anführungszeichen, `\n` für einen Zeilenumbruch, `\t` für einen Tabulator. Mit `+` werden Strings
**verkettet**. In **Template-Literalen** (Backticks) wird `${…}` berechnet und eingesetzt (JS2, Folien 28–31).

✏️ Bei `${100 / 2}` habe ich notiert: Hier steht **JavaScript-Code** mitten im String.

📘 **Globale Variablen** (JS2, Folien 34–39): Ohne `var`, `let` oder `const` wird eine Variable automatisch **global**, auch
innerhalb einer Funktion. Das sollte man vermeiden. Mit `var` in einer Funktion ist sie **lokal** und außerhalb unbekannt.

✏️ Meine Notiz zu Folie 38: Ohne Schlüsselwort gilt `y = 17` global, mit `var`/`let` wäre es lokal. Die Reihenfolge zählt:
① `funktion1()` definiert `y`, ② `funktion2()` zeigt `y` an → 17. Wird zuerst `funktion2()` aufgerufen, gibt es einen **Fehler**,
weil `y` noch nicht definiert ist.

📘 **`null` und `undefined`** (JS2, Folie 42): `undefined` haben Variablen ohne Wert, nicht vorhandene Eigenschaften und
Funktionen ohne Rückgabewert. `null` ist ein Schlüsselwort. Wer „kein Wert“ ausdrücken will, setzt `null`, nicht `undefined`.

✏️ Meine Notiz: `null` ist ein Schlüsselwort für eine **Referenz, die nicht vorhanden ist** (Verweis auf ein Objekt).

### Teil 6 – Operatoren, Kontrollstrukturen, Arrays, Objekte

📘 **Vergleichsoperatoren** (JS2, Folie 43): `==` und `!=` vergleichen den Wert, `===` und `!==` **zusätzlich den Datentyp**.

✏️ Mein Beispiel: `x = 5`, `y = '5'`. `x == y` ist `true`, weil hier aus der Zahl Text wird. `x === y` ist `false`, weil zusätzlich
der Datentyp verglichen wird.

📘 **Arithmetische Operatoren** (JS2, Folie 44): `+ - * / %` (Rest), `**` (Potenz), `++` und `--`.
**Logische Operatoren** (Folie 45): `!` (nicht), `&&` (und), `||` (oder).
**Spezielle Operatoren** (Folie 46): Bedingungsoperator `bedingung ? wert1 : wert2`, `delete`, `in`, `instanceof`, `typeof`.

✏️ Zum Bedingungsoperator: Das ist die Kurzform von `if (Bedingung) { … } else { … }`.

📘 **Kontrollstrukturen** (JS2, Folien 47–48): `if/else`, `while`, `do … while` und `for`.

📘 **Arrays** (JS2, Folien 40–41) sind Objekte. Man erzeugt sie mit `new Array()` oder kürzer mit `[ … ]`. Wichtige Methoden:
`push`, `pop`, `shift`, `unshift`, `slice`, `splice`, `concat`, `join`, `reverse`, `sort`, `forEach`, **`filter`**, **`map`**, `reduce`.

✏️ `filter` und `map` habe ich eingekreist: Beide machen aus einem Array ein **neues Array**.

📘 **Objekte** (JS2, Folien 49–51) sind Container für **Schlüssel-Wert-Paare**. Werte können Literale, Funktionen (Methoden) oder
andere Objekte sein. Zugriff mit Punkt (`person.firstName`) oder eckigen Klammern (`person['lastName']`). Objekte sind
veränderbar.

✏️ Meine Notiz zur Objekt-Literal-Schreibweise: erzeugt **einmal** ein Objekt.

📘 **Programmstruktur** (JS2, Folien 52–58): `for`-Schleife, die mit `ausgabe.innerHTML +=` Text in ein `<div>` schreibt, und das
Spiel **Zahlenraten** mit einer `while`-Schleife und der Variablen `fertig`. Wichtig: **`prompt` liefert immer einen String**, auch
wenn man eine Zahl eingibt.

> 🤖 **Korrektur zu JS2, Folie 58:** Dort steht, dass `prompt()` bei „Abbrechen“ `false` zurückgibt. In heutigen Browsern ist es
> **`null`**. Für `if (!eingabe)` ist das egal, weil `null`, `false` und `""` alle als „falsch“ gelten.

> 🤖 **Achtung bei JS2, Folien 50–51:** `person[lastName]` ohne Anführungszeichen sucht eine **Variable** `lastName`. Richtig ist
> `person['lastName']` mit Anführungszeichen, so wie auf Folie 51 beim Schreiben.

### Übung – Sternchen-Dreieck (JS2, Abgabe)

📘 Schreibe ein Programm, das mit **geschachtelten Schleifen** ein `*`-Dreieck in HTML ausgibt. Die Benutzerin soll vorher die
Anzahl der Zeilen eingeben. Die Ausgabe zusätzlich auf der Konsole machen. **Abgabe:** Quellcode und laufende Funktion in der
Vorlesung zeigen (JS2, Folie 59).

✏️ Mein Code liegt im Repo `wp-aufgaben-3-semester`, Ordner `12.10_Aufg3_Abschluss/`.

**▶ [Sternchen-Dreieck live ansehen](aufgaben/12.10_Aufg3_Abschluss/index.html)**

<details>
<summary>Lösung</summary>

```html
<button onclick="dreieckZeichnen()">Dreieck zeichnen</button>
<pre id="ausgabe"></pre>

<script>
  function dreieckZeichnen() {
    var eingabe = prompt("Anzahl der Zeilen:", "5");
    if (!eingabe) {
      alert("Keine Eingabe!");
      return;
    }
    var anzahl = parseInt(eingabe);
    console.log("Anzahl der Zeilen: " + anzahl);

    var ergebnis = "";
    for (var zeile = 1; zeile <= anzahl; zeile++) {        // äußere Schleife: Zeilen
      for (var stern = 1; stern <= zeile; stern++) {       // innere Schleife: Sterne
        ergebnis = ergebnis + "*";
      }
      ergebnis = ergebnis + "\n";                          // Umbruch nach jeder Zeile
    }

    console.log(ergebnis);
    document.getElementById("ausgabe").textContent = ergebnis;
  }
</script>
```

🤖 **Warum funktioniert das?**
- `prompt` liefert einen String. `parseInt` macht daraus eine Zahl (JS2, Folie 58).
- Die **äußere** Schleife läuft einmal pro Zeile. Die **innere** Schleife läuft so oft, wie die aktuelle Zeilennummer groß ist: in Zeile 1 einmal, in Zeile 3 dreimal. So wächst das Dreieck.
- `"\n"` ist der Zeilenumbruch (JS2, Folie 29). Im `<pre>`-Element bleiben Zeilenumbrüche sichtbar. In einem normalen `<p>` würde der Browser sie als Whitespace ignorieren.
- `textContent` schreibt den Text ins HTML, `console.log` in die Konsole. Damit sind beide Anforderungen erfüllt.

🤖 **Code-Check:** Erfüllt die Aufgabe. Verbesserungsideen:
- `let` statt `var` (JS2, Folie 33: `var` nur in Ausnahmefällen).
- Gibt man Buchstaben ein, liefert `parseInt` `NaN`, und es erscheint still nichts. Besser: `if (Number.isNaN(anzahl)) { alert("Bitte eine Zahl eingeben!"); return; }`
- Die Einrückung der inneren Schleife ist im Original verrutscht. Für den Browser egal, für Menschen schwerer zu lesen.

Zum Ausprobieren ohne `prompt`:

```js
const anzahl = 5;
let ergebnis = "";
for (let zeile = 1; zeile <= anzahl; zeile++) {
  for (let stern = 1; stern <= zeile; stern++) {
```
