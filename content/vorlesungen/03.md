## Überblick

📘 In JavaScript sind Funktionen „first class“: Man kann sie Variablen zuweisen, an andere Funktionen übergeben und als Rückgabewert verwenden (vorl3, Folie 2). Die Vorlesung zeigt dafür die verschiedenen Schreibweisen, besonders Pfeilfunktionen, und baut darauf reine Funktionen und Higher-Order-Functions auf.

📘 Der HTML-Teil erklärt das „HT“ in HTML: **Hypertext**. Mit dem `<a>`-Element verlinkt man Seiten. Liegen die Dateien in Unterordnern, braucht man **relative Pfade** (HTML2, Folie 4).

## Zusammenfassung

### Teil 1 – JavaScript-Funktionen

#### Funktionen erzeugen (vorl3, Folien 2–4)

📘 Es gibt vier Wege, eine Funktion zu erstellen:

1. über eine **Funktionsanweisung**: `function add(a, b) { … }`
2. über einen **Funktionsausdruck**: `const add = function(a, b) { … };`. Der Name hinter `function` darf fehlen, dann ist es eine anonyme Funktion.
3. über den Konstruktor des `Function`-Objekts
4. als **Pfeilfunktion**

📘 Parameter haben in JavaScript keinen Typ. Soll `add` nur Zahlen annehmen, muss man selbst prüfen, z. B. mit `typeof number1 !== 'number'`, und dann einen `TypeError` werfen (Folie 3).

#### Pfeilfunktionen `=>` (Folien 5–9)

📘 Statt `function` steht ein Pfeil **hinter** der Parameterliste: „Diese Eingabe (die Parameter) ruft dieses Ergebnis (den Rumpf) hervor.“

📘 Es gibt Kurzformen:

- Bei **genau einem** Parameter dürfen die Klammern weg: `x => x * x`.
- Besteht der Rumpf nur aus **einem Ausdruck**, dürfen `{ }` und `return` weg. Der Wert wird dann automatisch zurückgegeben.
- Hat die Funktion **keine** Parameter, schreibt man ein leeres Klammerpaar: `() => …`.

📘 Ein Vorgriff (Folie 9): Wichtiger als die kürzere Schreibweise ist das sogenannte `this`-Binding. Es kommt später.

> ❓ **Offen:** Das `this`-Binding wird nur erwähnt. Wann wird es behandelt?

#### Parameter vs. Argumente, `arguments`, Rest-Parameter (Folien 10–16)

📘 **Parameter** sind die Namen in der Klammer bei der *Deklaration*. **Argumente** sind die Werte, die man beim *Aufruf* übergibt (Folie 12).

📘 Jede (normale) Funktion hat intern ein Objekt `arguments` mit allen übergebenen Argumenten. Es ist „arrayähnlich“: Es hat `length` und Indizes, aber keine Array-Methoden wie `forEach` (Folie 10).

📘 Seit ES2015 gibt es die bessere Lösung, die **Rest-Parameter** `...name`. Sie sammeln alle *überzähligen* Argumente in einem **echten Array**, vergleichbar mit Varargs in Java (Folien 11, 14–16).

✏️ Diese Folie habe ich fotografiert: Rest Parameters sammeln überzählige Argumente in einem Array.

#### Spread-Syntax (Folien 11, 17–24)

📘 Spread sieht gleich aus (`...`), macht aber das **Gegenteil** von Rest: Es *verteilt* die Elemente eines Arrays oder Objekts. Damit kann man:

- ein Array oder Objekt in ein anderes einfügen: `[...a, 'x']`, `{ ...person, age: 27 }`
- mehrere Arrays oder Objekte verbinden: `[...asien, ...europa]`
- Arrays und Objekte **kopieren**: `{ ...person1 }`

📘 Das Kopieren ist wichtig, weil Objekte und Arrays per **Referenz** kopiert werden. Nach `let person2 = person1;` zeigen beide Variablen auf *dasselbe* Objekt. Ändert man `person1.name`, ändert sich auch `person2` (Folien 22–23). Mit `{ ...person1 }` entsteht ein neues Objekt (Folie 24).

> 🤖 **KI-Erklärung – Rest oder Spread?** Achte darauf, *wo* die drei Punkte stehen. In der **Parameterliste** einer Funktion sammeln sie Werte ein: Das ist Rest. Beim **Aufruf** oder in `[ ]` und `{ }` packen sie Werte aus: Das ist Spread. Spread kopiert nur die oberste Ebene. Verschachtelte Objekte werden weiter geteilt.

#### Funktionen als Werte (Folie 25)

📘 Eine Variable mit einer Funktion ist eine ganz normale Bindung. Sie kann neu belegt werden, sofern sie nicht `const` ist. Beispiel aus dem Skript: `launchMissiles` wird im `safeMode` durch eine leere Funktion ersetzt.

#### Seiteneffekte und reine Funktionen (Folien 26–29)

📘 Manche Funktionen ruft man wegen ihrer **Seiteneffekte** auf, z. B. einer Ausgabe. Bei anderen zählt der **Rückgabewert**. Eine Funktion kann auch beides haben.

📘 Eine **reine Funktion** (pure function) gibt einen Wert zurück, der **nur aus ihren Parametern** entsteht. Sie hat keine Seiteneffekte, verändert keine globalen Variablen und nicht den Zustand der Anwendung. Mit denselben Argumenten liefert sie immer dasselbe Ergebnis. Deshalb ist sie leicht zu testen (Folien 27–28).

📘 Seiteneffekte sind trotzdem oft nützlich. Von `console.log` gibt es z. B. keine reine Version (Folie 29).

#### Higher-Order-Functions (Folien 30–34)

📘 Higher-Order-Functions **nehmen Funktionen als Parameter** oder **geben Funktionen zurück**. Beispiele sind `Array.map`, `Array.filter` und `Array.reduce`.

📘 Eine Funktion als Rückgabewert: `wrapValue(n)` gibt `() => local` zurück, und `multiplier(factor)` gibt `number => number * factor` zurück. Die zurückgegebene Funktion **merkt sich** den Wert (`n` bzw. `factor`), auch wenn die äußere Funktion längst fertig ist.

✏️ Laut meiner Notiz zum Foto ging es darum, dass Funktionen andere Funktionen zurückgeben können und die zurückgegebene Funktion sich den Faktor merkt.

> 🤖 **KI-Erklärung – Closure:** Dieses „Merken“ heißt **Closure**. Jeder Aufruf von `multiplier` erzeugt eine eigene kleine Umgebung mit eigenem `factor`. `twice` hat `factor = 2`. Ein `thrice = multiplier(3)` hätte seine eigene Umgebung mit `factor = 3`. Das Wort „Closure“ steht nicht im Skript.

### Teil 2 – HTML: Hypertext und Links (HTML2)

#### Das `<a>`-Element (Folien 4–18)

📘 Mit `<a>` erstellt man einen Hypertext-Link auf eine andere Seite:

- Der **Inhalt** zwischen `<a>` und `</a>` ist die anklickbare **Beschriftung**. Er wird standardmäßig unterstrichen angezeigt.
- Das **`href`-Attribut** sagt dem Browser das **Ziel** (Folie 17).
- Klickt man auf den Link, lädt der Browser die Seite aus `href` (Folie 18).
- Auch ein `<img>` kann als Beschriftung zwischen den `<a>`-Tags stehen (Folie 26).

#### Attribute (Folien 19–23)

📘 Attribute geben einem Element zusätzliche Informationen, z. B. `href` bei `<a>`, `src` bei `<img>` und `type` bei `<style>`. Sie werden immer gleich geschrieben: `name="wert"`, mit doppelten Anführungszeichen. Man kann **keine eigenen Attribute erfinden**: Der Browser versteht nur die definierten und unterstützten (Folien 21–23).

#### Ordner und relative Pfade (Folien 27–47)

📘 Größere Websites gliedert man in Ordner. Der oberste Ordner heißt **Root-Verzeichnis**. Bei der KopfüBar ist das `bar/`, mit den Unterordnern `info/`, `getraenke/` und `bilder/` (Folien 28–29).

📘 Nach dem Verschieben sind Links und Bilder kaputt. Ein Bild, das nicht gefunden wird, nennt man „defektes Bild“ (Folie 32). Die Lösung sind **relative Pfade**: der Weg *von der aktuellen Datei* zur Zieldatei (Folien 33–34).

| Richtung | Schreibweise | Beispiel aus der Bar |
|---|---|---|
| in einen Unterordner | `ordner/datei` | `getraenke/elixir.html` |
| eine Ebene höher | `../datei` | `../bar.html` |
| zwei Ebenen höher | `../../datei` | – |
| hoch und wieder runter | `../ordner/datei` | `../bilder/rot.jpg` |

📘 Wichtige Regeln (Folien 41–43, 50):

- `..` bedeutet „übergeordnetes Verzeichnis“.
- Die Teile eines Pfads trennt man immer mit `/`, nie mit `\`, auch unter Windows nicht.
- Nach oben kommt man höchstens bis zum Root-Verzeichnis.
- Keine Leerzeichen in Datei- und Ordnernamen.
- `src` bei `<img>` funktioniert mit relativen Pfaden genauso wie `href`.

> 🤖 **KI-Erklärung:** Lies einen relativen Pfad wie eine Wegbeschreibung von dem Ordner aus, in dem die *aktuelle* Datei liegt. Ein Beispiel ist der Kopfnuss-Link „Zurück zur Bar“ (Folie 44): Er ist in `info/wegbeschreibung.html` und in `getraenke/elixir.html` identisch, nämlich `../bar.html`, weil beide Dateien eine Ebene unter `bar/` liegen. Vermeide außerdem Umlaute in Ordnernamen, z. B. `getraenke` statt `getränke`. Server und Git kommen damit oft nicht zurecht.

### Übung – Bohnen zählen (Abgabe, vorl3 Folie 35)

📘 Aufgabe:

1. `countBs(text)` gibt zurück, wie viele **große B** im String stehen.
2. `countChar(text, zeichen)` macht dasselbe für ein **beliebiges** Zeichen.
3. `countBs` so umschreiben, dass es `countChar` benutzt.
4. Das Ganze mit **Pfeilfunktionen** schreiben.

Hinweis aus dem Skript: Mit `"string"[N]` bekommt man das N-te Zeichen. Das erste Zeichen hat die Position 0, das letzte die Position `length - 1`.

📘 **Abgabe:** Quellcode und laufendes Programm im Übungsteil der Vorlesung zeigen, alternativ per Bildschirmaufnahme an den Dozenten mailen.

✏️ Die Lösung habe ich mit ChatGPT erarbeitet. Sie liegt lauffähig im Repo `wp-aufgaben-3-semester`, Ordner `19.10_aufgabe2_bohnen-zaehlen/`.

<details>
<summary>Lösung</summary>

```js
const countChar = (text, zeichen) => {
  let anzahl = 0;

  for (let i = 0; i < text.length; i++) {
    if (text[i] === zeichen) {
      anzahl++;
    }
  }

  return anzahl;
};

const countBs = text => countChar(text, "B");

console.log(countBs("BBC"));                 // 2
console.log(countChar("kakkerlak", "k"));    // 4
```

🤖 **Warum funktioniert das?** Zeile für Zeile:

- **`(text, zeichen) =>`**: `countChar` bekommt zwei Parameter. Beim Aufruf `countChar("kakkerlak", "k")` ist `text` gleich `"kakkerlak"` und `zeichen` gleich `"k"`.
- **`let anzahl = 0;`**: Der Zähler startet bei 0. Er steht mit `let` *innerhalb* der Funktion, damit jeder Aufruf neu bei 0 beginnt. So bleibt die Funktion rein.
- **`for (let i = 0; i < text.length; i++)`**:
  - `i` ist die Position im Text. Sie startet bei 0, weil das erste Zeichen Position 0 hat.
  - Die Bedingung lautet `<` und nicht `<=`: Bei einem Text der Länge 9 ist die letzte Position 8 (`length - 1`).
  - `i++` geht nach jedem Durchlauf eine Position weiter.
- **`text[i] === zeichen`**:
  - `text[i]` holt das einzelne Zeichen an Position `i`.
  - `===` vergleicht genau, also auch Groß- und Kleinschreibung. Deshalb zählt `countBs("bbb")` 0.
  - Nur wenn es passt, wird `anzahl` um 1 erhöht.
- **`return anzahl;`**: Nach der Schleife wird das Ergebnis zurückgegeben. Weil der Rumpf mehrere Anweisungen hat, braucht man `{ }` und ein ausdrückliches `return`.
- **`const countBs = text => countChar(text, "B");`**:
  - Das ist die Kurzform der Pfeilfunktion: ein Parameter ohne Klammern und ein einzelner Ausdruck ohne `return`.
  - `countBs` zählt nicht selbst, sondern **gibt die Arbeit weiter** an `countChar` und legt das Zeichen auf `"B"` fest.

Andere Lösungen zum Vergleich (ohne Schleife):

```js
const countChar2 = (text, zeichen) => text.split(zeichen).length - 1;
const countChar3 = (text, zeichen) => [...text].filter(c => c === zeichen).length;
```

`countChar3` nutzt zwei Themen aus der Vorlesung: Spread (`[...text]` macht aus dem String ein Array von Zeichen) und die Higher-Order-Function `filter`.

</details>
