## Überblick

Jede Webseite entsteht durch ein Gespräch zwischen zwei Rechnern: Der **Browser** (Client) fragt an, der **Server** antwortet. Die gemeinsame Sprache dieses Gesprächs heißt **HTTP**.

## Lernziele

- Ich kann das Client-Server-Prinzip mit eigenen Worten erklären.
- Ich kenne den Ablauf einer HTTP-Anfrage.
- Ich kann die Rollen von HTML, CSS und JavaScript unterscheiden.

## Zusammenfassung

### Client und Server

Der Client ist das Programm, das Inhalte anfordert und anzeigt – meist ein Browser. Der Server stellt die Dateien bereit und schickt sie auf Anfrage zurück.

### Der Weg einer Anfrage

1. Die Adresse (URL) wird eingegeben.
2. Der Browser sendet eine HTTP-Anfrage an den Server.
3. Der Server antwortet mit einem Statuscode und den Dateien.
4. Der Browser setzt HTML, CSS und JavaScript zu einer Seite zusammen.

## Beispiele

Eine HTTP-Anfrage in vereinfachter Form:

```http
GET /index.html HTTP/1.1
Host: www.beispiel.de
```

Typische Statuscodes: `200` (OK), `404` (nicht gefunden), `500` (Serverfehler).

## Übungen

### Übung 1 – Anfrage beobachten

Öffne eine beliebige Website, drücke `F12` und wechsle in den Tab **Netzwerk**. Lade die Seite neu. Wie viele Anfragen werden gestellt?

<details>
<summary>Lösungshinweis</summary>

Die Zahl hängt von der Seite ab. Wichtig ist die Erkenntnis: Eine Seite besteht aus vielen einzelnen Dateien (HTML, CSS, JavaScript, Bilder), die alle einzeln angefragt werden.

</details>

### Übung 2 – Statuscodes

Rufe eine Adresse auf, die es nicht gibt, z. B. `/gibt-es-nicht`. Welchen Statuscode bekommst du?

<details>
<summary>Lösung</summary>

`404 Not Found` – der Server ist erreichbar, aber die angefragte Datei existiert nicht.

</details>
