## Überblick

📘 Alles, was auf einer Webseite passiert, ist ein **Event**: Laden, Klicken, Tippen, Scrollen, Fenstergröße ändern (vorl7-1,
Folie 24). Die Vorlesung zeigt, wie der Browser Events in einer **Event-Queue** sammelt und abarbeitet, welche drei Wege es gibt,
darauf zu reagieren – vom alten `onclick`-Attribut bis zum empfohlenen **Event-Listener** –, und wie jQuery das vereinheitlicht.
Teil 2 geht eine Ebene höher: Das **Browser Object Model** mit dem `window`-Objekt steuert Fenster, Adresse und Verlauf. Als
Praxisbeispiel entsteht ein **Akkordeon**, das Inhalte platzsparend ein- und ausklappt.

## Lernziele

- Ich kann mit dem Event-Objekt arbeiten und das Standardverhalten mit `preventDefault()` verhindern.
- Ich kann mit jQuery Events verknüpfen und Code erst nach dem Laden mit `$(document).ready()` ausführen.
- Ich kann erklären, was das Browser Object Model ist, und `window`, `location` und `history` nutzen.

## Zusammenfassung

### Teil 1 – Was sind Events? (vorl7-1, Folien 3–7, 24–29)

📘 Wird ein Ereignis ausgelöst, kommt es in die **Event-Queue**. Was zuerst ausgelöst wurde, wird zuerst behandelt. Die
**Event-Loop** prüft fortlaufend, ob ein neues Ereignis wartet, und gibt es an die zuständigen **Event-Handler** weiter. Das sind in
JavaScript einfache Funktionen (Folien 4–5).

📘 Damit eine Seite auf ein Event reagiert, braucht es drei Schritte (Folien 6, 28–29):

1. das **Element** auswählen, das reagieren soll (wie in Vorlesung 6)
2. das **Event** festlegen, z. B. `click`
3. die **Funktion** angeben, die dann ausgeführt wird

✏️ Das kenne ich aus Vorlesung 1: JavaScript reagiert vor allem auf Benutzer-Ereignisse, ähnlich wie ein Action Listener in Java.

### Teil 2 – Drei Wege, auf Events zu reagieren (Folien 8–13, 43–49)

| Weg | Beispiel | Bewertung im Skript |
|---|---|---|
| **HTML-Event-Handler** | `<button onclick="los()">` | sollte nicht mehr verwendet werden: HTML und JavaScript sind vermischt (Folien 8, 43) |
| **DOM-Event-Handler** („traditionelles Modell“) | `window.onload = meldung;` | trennt HTML und JS, aber nur **eine** Funktion pro Event und Element (Folien 9, 44–47) |
| **DOM-Event-Listener** | `element.addEventListener('click', los);` | seit DOM Level 2 (2000) der **empfohlene** Standard, beliebig viele Listener (Folien 10–13, 48) |

📘 Wichtig beim traditionellen Modell: `window.onload = meldung;` **ohne** Klammern. Mit Klammern würde die Funktion sofort
ausgeführt und ihr Ergebnis zugewiesen statt der Funktion selbst (Folie 46). Event-Listener dürfen auch anonyme Funktionen oder
**Pfeilfunktionen** sein (Folien 12–13).

### Teil 3 – Die wichtigsten Events (Folien 15–22, 30–38)

- **Maus:** `click`, `dblclick`, `mousedown`/`mouseup`, `mouseover`/`mouseout`, `mouseenter`/`mouseleave`, `mousemove`
- **Dokument & Fenster:** `load` (Seite fertig geladen), `unload`, `resize`, `scroll`
- **Formular:** `submit`, `reset`, `change`, `input`, `focus` / `blur` (Feld bekommt bzw. verliert den Fokus)
- **Tastatur:** `keydown`, `keypress`, `keyup`

📘 `mouseenter`/`mouseleave` lösen nur am Element selbst aus, `mouseover`/`mouseout` zusätzlich beim Wechsel zwischen Kindelementen
(Folie 16). Ein Beispiel für `blur`: Prüfen, ob ein eingegebenes Alter negativ ist, sobald man das Feld verlässt (Folien 11–13).

### Teil 4 – Event-Objekt und Standardverhalten (Folien 79–86)

📘 Bei jedem Event legt der Browser ein **Event-Objekt** an: Mauskoordinaten, auslösendes Element, gedrückte Taste, ob Shift oder Alt
gehalten wurde (Folien 79–80). Mit **`preventDefault()`** verhindert man die normale Reaktion, etwa dass ein Link eine neue Seite lädt
oder ein Formular abgeschickt wird (Folien 81–82).

### Teil 5 – Events mit jQuery (Folien 51–78)

📘 jQuery vereinheitlicht die Event-Behandlung für alle Browser (Folie 49). Muster: **Auswahl → Event → anonyme Funktion**, z. B.
`$('a').mouseover(function() { … });` (Folien 52–56). Weitere Konzepte (Folien 67–78):

- **`$(document).ready()`** führt den Code aus, sobald das **HTML** geladen ist – ohne auf langsame Bilder zu warten wie beim
  `load`-Event. Gehört in jede Seite mit jQuery (Folien 68–73).
- **`hover()`** fasst `mouseover` und `mouseout` zusammen, z. B. für Untermenüs (Folien 74–77).
- **`toggle()`** wechselt bei jedem Klick zwischen zwei Funktionen (Folie 78).

### Teil 6 – Das Browser Object Model (vorl7-2, Folien 3–16)

📘 Neben dem DOM gibt es das **BOM**: Es steuert den Browser selbst, z. B. vor und zurück im Verlauf, und liefert Informationen wie
Größe und Position des Fensters. Einstieg ist das globale **`window`**-Objekt – eines pro Browsertab. Es ist auch der Einstieg in
HTML5-APIs wie Geolocation und Storage (Folien 4–6).

📘 Wichtige Eigenschaften (Folien 7–10): `location` (aktuelle URL und ihre Teile), `history` (Verlauf), `navigator` (Browser-Infos),
`screen` (Bildschirm), `innerWidth` / `innerHeight` (Größe des Fensterinhalts). Methoden wie `moveBy()` und `moveTo()` verschieben
ein Fenster.

📘 **`window.open(url, name, optionen)`** öffnet ein neues Fenster mit Breite, Höhe und weiteren Optionen. Die Rückgabe ist eine
Referenz, über die man das Fenster später wieder schließen kann (Folien 13–14). jQuery liefert die Größen von Fenster und Dokument mit
`$(window).height()` und `$(document).height()` (Folien 15–16).

### Teil 7 – Akkordeon mit jQuery UI (vorl7-2, Folien 19–41)

📘 Zu viel Information auf einer Seite überfordert. Ein **Akkordeon** zeigt Inhalte in Bereichen, von denen immer nur einer offen ist
(Folien 19–20). Das Accordion-Plug-in aus **jQuery UI** erwartet einen Container mit abwechselnd Überschrift und Inhalt, z. B.
`<h2>` + `<div>` oder eine Definitionsliste `<dl>` mit `<dt>` und `<dd>` (Folien 23–25). Aufgerufen wird es in `ready()` mit einem
**Objekt-Literal** als Optionen, z. B. `header: 'h2'` oder `active: '.oeffne'` für den Bereich, der beim Laden offen ist
(Folien 26–31). Das Aussehen steuert allein das CSS (Folie 33).

> 🤖 **Verbindung zu diesem Portfolio:** Die Lösungen in den Kapiteln klappen ohne JavaScript auf – mit dem HTML-Element
> `<details>`. Und die Sticky Section auf der Startseite reagiert auf das Scrollen: nicht mit einem `scroll`-Event, sondern mit dem
> **Intersection Observer**, der nur meldet, wenn ein Element sichtbar wird. Das spart Rechenzeit.

## Beispiele

📘 Event-Listener mit Pfeilfunktion und `blur` – nach dem Alters-Beispiel (vorl7-1, Folien 11–13):

```html
<input id="age" type="number">
<p id="meldung"></p>
<script>
  const feld = document.getElementById('age');
  feld.addEventListener('blur', () => {
    const alter = Number(feld.value);
    document.getElementById('meldung').textContent =
      alter < 0 ? 'Das Alter darf nicht negativ sein.' : '';
  });
</script>
```

📘 Traditionelles Modell: Funktion **ohne** Klammern zuweisen (Folien 45–46):

```html
<script>
  function meldung() {
    alert("Willkommen ...");
  }
  window.onload = meldung;     // nicht: meldung()
</script>
```

📘 jQuery: Untermenü mit `hover()` und ein Link ohne Standardverhalten (Folien 75, 82):

```html
<script>
  $(document).ready(function () {
    $('#menue').hover(
      function () { $('#untermenue').show(); },
      function () { $('#untermenue').hide(); }
    );
    $('#menue').click(function (evt) {
      evt.preventDefault();          // Link lädt keine neue Seite
    });
  });
</script>
```

🤖 Ohne Browser zum Ausprobieren: Event-Queue im Kleinen. Ereignisse werden gesammelt und der Reihe nach an ihre Handler gegeben:

```js
const queue = [];
const handler = {
  click: e => "Klick auf " + e.ziel,
  keydown: e => "Taste " + e.taste
};
queue.push({ typ: "click", ziel: "Button" });
queue.push({ typ: "keydown", taste: "Enter" });
queue.push({ typ: "click", ziel: "Link" });

while (queue.length > 0) {             // die "Event-Loop"
  const event = queue.shift();         // zuerst ausgelöst = zuerst behandelt
  console.log(handler[event.typ](event));
}
```

📘 Akkordeon mit jQuery UI (vorl7-2, Folien 24, 27, 31):

```html
<div id="akkordeon">
  <h2>Akkordeon 1</h2>
  <div>Inhalt für Bereich 1</div>
  <h2 class="oeffne">Akkordeon 2</h2>
  <div>Inhalt für Bereich 2</div>
</div>
<script>
  $(document).ready(function () {
    $('#akkordeon').accordion({
      header: 'h2',
      active: '.oeffne'
    });
  });
</script>
```
