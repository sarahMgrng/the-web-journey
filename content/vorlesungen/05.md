## Zusammenfassung

### Teil 1 – Was ist ein Objekt? (vorl5, Folien 3–13)

📘 Ein Objekt ist ein **Behälter** mit einem Namen. Es enthält Daten (**Eigenschaften**, auch Attribute) und Werkzeuge, um mit den
Daten zu arbeiten (**Methoden**, also Funktionen, die zu einem Objekt gehören) (Folien 4–7). Wie ein Auto, das eine Farbe hat
(Eigenschaft) und fahren kann (Fähigkeit). Anders als bei normalen Variablen gibt es immer den Bezug zu einem Objekt (Folie 8).

📘 Manche Objekte gibt es automatisch, z. B. das Browserfenster. Andere erzeugt ein **Konstruktor** mit `new`:
`new String("JavaScript")` (Folien 10–11). Zugriff mit Punkt: `str.length`, `str.indexOf("Script")` (Folien 12–13).

### Teil 2 – Objekte erzeugen (Folien 14–33)

📘 Die Wege im Überblick (Folie 10):

| Weg | Beispiel | Wann? |
|---|---|---|
| allgemeiner Konstruktor | `const p = new Object(); p.name = "Fred";` | Eigenschaften entstehen erst beim Zuweisen (Folien 14–16) |
| Objekt-Literal | `{ name: "Fred", begruessung() { … } }` | **ein** einzelnes Objekt, kurz und lesbar (Folien 19–21) |
| Konstruktorfunktion | `function Person(n) { this.name = n; }` + `new Person("Fred")` | viele gleich aufgebaute Objekte (Folien 27–30) |
| Klasse | `class Hund { constructor() { … } }` | moderne Schreibweise, wie in Java (Folie 34) |

📘 Beim Literal stehen **Doppelpunkt** statt `=` und **Komma** zwischen den Eigenschaften. Eine Methode wird als Funktion hinterlegt
und mit `objekt.methode()` aufgerufen. Bei der Definition stehen keine Klammern, denn es ist noch kein Aufruf (Folien 16, 20).

### Teil 3 – JSON (Folien 19–26)

📘 **JSON** (JavaScript Object Notation, gesprochen „Jason“) ist eine Teilmenge der Objekt-Literal-Schreibweise und wird vor allem
genutzt, um Objekte als **Text über das Netzwerk** zu schicken (Folie 19). Die Regeln sind strenger (Folie 23):

- alle Namen in **doppelten** Anführungszeichen
- nur einfache Werte – keine Funktionen, keine Berechnungen
- keine Kommentare

📘 `JSON.stringify(objekt)` macht aus einem Objekt einen JSON-String, `JSON.parse(text)` macht aus dem String wieder ein Objekt
(Folien 22–26). Der Client verpackt Daten mit `stringify`, schickt sie über das Internet zum Server und packt die Antwort mit
`parse` wieder aus (Folie 24).

> 🤖 **Verbindung zu Vorlesung 2 und zu diesem Portfolio:** Hier schließt sich der Kreis zu HTTP-Anfrage und -Antwort. Ein Server
> schickt nicht nur HTML, sondern oft JSON. Dieses Portfolio holt seine Kapitel ebenfalls per `fetch()` als Text vom Server –
> allerdings als Markdown statt JSON.

### Teil 4 – Klassen, Kontext und `this` (Folien 34–43)

📘 In Klassen stehen Methoden. Eigenschaften legt man im `constructor` über `this` an (Folie 34).

📘 `this` funktioniert in JavaScript anders als in Java oder C#: Es zeigt nicht auf das Objekt, in dem die Funktion **definiert**
wurde, sondern auf das Objekt, auf dem sie **aufgerufen** wird – den Ausführungskontext (Folien 35–36). Die Regeln (Folie 43):

- **globale Funktion:** `this` ist das globale Objekt (im strikten Modus `undefined`)
- **Objektmethode:** `this` ist das Objekt
- **Konstruktor mit `new`:** `this` ist das neu erzeugte Objekt

📘 Gibt man eine Methode weiter (z. B. `const f = hund.printType;`), geht der Bezug verloren. Abhilfe: `hund.printType.bind(hund)`
oder die Methode als **Pfeilfunktion** schreiben, die `this` von außen mitnimmt (Folien 37–38). Damit ist das in Vorlesung 3
angekündigte „`this`-Binding“ erklärt.

### Teil 5 – Kapselung: private Eigenschaften (Folien 44–51)

📘 Früher wurden private Eigenschaften mit lokalen Variablen im Konstruktor nachgebaut. Nur **privilegierte öffentliche Methoden**,
die im Konstruktor auf `this` definiert sind, kommen an sie heran (Folien 44–47).

📘 Seit **ES2022** gibt es echte private Eigenschaften und Methoden: Man stellt dem Namen ein **`#`** voran. Von außen ist der Zugriff
nicht möglich, nur Methoden der Klasse kommen heran. Mit `get` und `set` baut man kontrollierte Zugänge (Folien 48–51).

### Teil 6 – Destructuring, Literal Enhancement, Spread (Folien 53–64)

📘 **Destructuring** löst einzelne Werte aus Arrays oder Objekten heraus: `const { name, ...rest } = objekt;` (Folien 53–62).
**Object Literal Enhancement** ist das Gegenstück und baut aus Variablen wieder ein Objekt: `const berg = { name, hoehe };`
(Folie 63). Der **Spread-Operator** verbindet Arrays oder Objekte zu neuen (Folie 64) – kennen wir aus Vorlesung 3.

## Beispiele

📘 Objekt-Literal mit Methode und JSON hin und zurück (vorl5, Folien 21–26):

```js
const person1 = {
  name: "Fred",
  begruessung: function () {
    return "Hallo " + this.name + "!";
  }
};
console.log(person1.begruessung());           // Hallo Fred!

const text = JSON.stringify({ name: "John Doe", age: 27 });
console.log(text);                              // {"name":"John Doe","age":27}
const obj = JSON.parse(text);
console.log(obj.age + 1);                       // 28
```

📘 `this` hängt vom Aufruf ab, und `bind` hält es fest (nach Folien 37–42):

```js
class Hund {
  constructor() {
    this.type = "Dackel";
  }
  printType() {
    return this.type;
  }
}
const hund = new Hund();
console.log(hund.printType());                 // Dackel

const ohneBind = hund.printType;
try {
  ohneBind();
} catch (fehler) {
  console.log("Fehler: " + fehler.message);    // this ist undefined
}

const mitBind = hund.printType.bind(hund);
console.log(mitBind());                        // Dackel
```

📘 Echte private Eigenschaften mit `#`, Getter und Setter (nach Folien 49–51):

```js
class Animal {
  #name;
  #color;
  constructor(name, color) {
    this.#name = name;
    this.#color = color;
  }
  get name() { return this.#name; }
  set name(neu) { this.#name = neu; }
  toString() { return `${this.#name}, ${this.#color}`; }
}

const snake = new Animal("Zischi", "Grün");
console.log(snake.name);         // Zischi
snake.name = "Sssami";
console.log(snake.toString());   // Sssami, Grün
console.log(snake.color);        // undefined – #color ist von außen nicht sichtbar
```

📘 Destructuring und Literal Enhancement (Folien 53, 63):

```js
const meinObjekt = { name: "Maier", nachname: "Müller", alter: 30 };
const { name, ...rest } = meinObjekt;
console.log(name);    // Maier
console.log(rest);    // {nachname: "Müller", alter: 30}

const [a, b, ...weitere] = [44, 67, 90, 56, 877];
console.log(a, b, weitere);   // 44 67 [90, 56, 877]

const berg = "Zugspitze", hoehe = 2962;
console.log({ berg, hoehe }); // {berg: "Zugspitze", hoehe: 2962}
```

**Top-Learning: Private Felder bleiben privat – auch im JSON.** Eine Klasse kapselt Daten mit `#`. `JSON.stringify` sieht nur die öffentlichen Eigenschaften.

```js
class Kontakt {
  #telefon;
  constructor(name, telefon) { this.name = name; this.#telefon = telefon; }
  get telefon() { return this.#telefon.slice(0, 4) + "…"; }
}
const k = new Kontakt("Ada", "0621123456");
console.log(JSON.stringify(k));   // {"name":"Ada"}
console.log(k.telefon);           // 0621…
```
